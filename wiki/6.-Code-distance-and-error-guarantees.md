# Code distance and error guarantees

How can we recognise a corrupted message, and when can we recover the
message that was sent? We can separate these questions by measuring the
distance between the words of a code.

We consider a finite set $C$ of at least two distinct binary words of the
same positive length $n$. An error changes a bit from `0` to `1` or from
`1` to `0`, without inserting or deleting positions. Its _weight_ is the
number of positions in which the received word differs from the word sent.

## We count differing positions

The Hamming distance $d(x,y)$ counts positions where two words differ.
For example, `000` and `011` differ in two positions, so their distance
is two. The minimum distance of a code is

```math
d_{\min}
=\min_{\substack{x,y\in C\\x\ne y}}d(x,y).
```

For the repetition code $C=\{000,111\}$, the only pair of distinct
codewords has distance three. Therefore $d_{\min}=3$.

## Detection and correction answer different questions

We can _detect_ an error by checking whether the received word belongs
to $C$. A received word outside $C$ shows that corruption occurred.
An error that changes one valid codeword into another escapes this check.

To _correct_ errors, we need to identify the word that was sent. If at
most $t$ bits changed, unique correction requires the sets of received
words within distance $t$ of different codewords to be disjoint.

| Guarantee for every transmitted codeword | Minimum-distance condition |
| --- | --- |
| Detect every nonzero error of weight at most $t$ | $d_{\min}>t$ |
| Uniquely correct every error of weight at most $t$ | $d_{\min}>2t$ |

Here $t$ is a nonnegative integer. The maximum guaranteed numbers are

```math
t_{\mathrm{detect}}=d_{\min}-1,
\qquad
t_{\mathrm{correct}}
=\left\lfloor\frac{d_{\min}-1}{2}\right\rfloor.
```

The factor of two comes from allowing errors around either possible
transmitted word. If a received word were within distance $t$ of two
codewords, the triangle inequality would put those codewords at distance
at most $2t$ from each other.

## We follow the three-bit example

Suppose we send `000` using $C=\{000,111\}$.

| Received word | Changed positions | Membership check | Nearest codeword |
| --- | ---: | --- | --- |
| `001` | 1 | Error detected | `000`, correct |
| `011` | 2 | Error detected | `111`, incorrect |
| `111` | 3 | No error detected | `111`, incorrect |

Every one-bit and two-bit error leaves the code, so membership detects
it. Only errors of at most one bit are always corrected by choosing
the nearest codeword. With two changed bits, detecting corruption does
not provide enough information to recover the original word.

The [[four-bit example in the second model|2.-Second-Model]] shows the
boundary another way: `0011` is equally close to `0000` and `1111`.
Two possible origins prevent guaranteed unique correction of two errors.

## We use the computational resource

The [block-code helper](https://github.com/JulTob/Linguistics/blob/07e5d67b7c1ade3eb9bec9f05e7155c57d1c4e39/topics/coding/block_codes.py)
calculates distances and worst-case guarantees. From the repository's
`topics/coding/` directory, we can use it in Python:

```python
from block_codes import (
        code_guarantees,
        hamming_distance,
        )


distance = hamming_distance(
        "000",
        "011",
        )

guarantees = code_guarantees(
        ["000", "111"],
        )

print(distance)
print(guarantees)
```

The distance is `2`. The returned record has word length `3`, codeword
count `2`, minimum distance `3`, detectable errors `2` and correctable
errors `1`. It reports the guarantees; a decoder is a separate operation.

The [topic-local tests](https://github.com/JulTob/Linguistics/blob/07e5d67b7c1ade3eb9bec9f05e7155c57d1c4e39/topics/coding/test_block_codes.py)
check all received three-bit words for the repetition-code guarantees,
as well as invalid inputs and a different code. We can run them from
the repository root:

```sh
python3 -B -m unittest discover -s topics/coding -v
```

## Sources & Inspiration

Solomon Marcus, Edmond Nicolau and Sorin Stati, _Introducción en la
lingüística matemática_, translated by Ramon Cerdá, Editorial Teide,
1978: §§10.6–10.8, printed pp. 315–317 / PDF pp. 332–334, for code
distance, detection and correction.

The general definitions in §§10.7–10.8 use the wording _por lo menos_
(at least) for the number of errors. The stated distance criteria require
the bounded interpretation _at most_ used here: the three-bit change
from `000` to `111` demonstrates why an unbounded lower-count guarantee
cannot hold. This is our local source qualification. The examples and
computational walkthrough above are our teaching application.
