# Linguistics project instructions

We keep operating directions here, separate from human topic explanations.
We read the relevant agent file and actual Wiki page before changing work.

## Shared rules

- We treat the actual [Wiki](https://github.com/JulTob/Linguistics/wiki)
  as the project's authoritative human reference. Only Julio edits and
  publishes it. We prepare individual Markdown proposals and precise
  incorporation steps; we do not edit or push actual Wiki working copies.
- We use neutral scientific European English and shared we-language.
  We use `_italics_`, `__bold__`, `___both___`, `$inline math$` and
  fenced `math` for displayed formulae in GitHub Markdown.
- We place used sources at the end of the page or notebook using them.
  We keep broader lookup records here instead of adding unused citations.
- We inspect source passages and code before changing them. We state a
  brief plan, then make small correct changes with truthful checks.
- We keep code and tests with their topic, using cohesive functions,
  clear domain types, useful failure messages and low-density waterfall
  layout. We expose meaningful intermediate results when they teach the
  method; we avoid unnecessary frameworks and dependencies.
- We distinguish a source's statement, a proved result, an empirical
  report and our new application. Local source qualifications accompany
  affected concepts. We use established valid methods plainly; a whole-book
  audit is not a prerequisite for ordinary work.
- We do not add private books, full OCR or credentials to this repository.
  A catalogue route does not grant access to another plugin's private files.
- We retain each agent's meaningful Reflection with that agent's maintained
  resources. Project records may link it; we do not create background
  memory, claim automatic learning or publish a proposal through Reflection.

## Roles

We use [Marcy's project binding](marcy.md) for continuous linguistic
modelling. Subject and language specialists retain their own methods;
we choose focused complementary checks for the actual uncertainty.
We keep source identity and access in [sources.json](sources.json).
